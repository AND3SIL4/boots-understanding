Boost Your Process
Understanding.

Documentación de RPA que se convierte en un grafo al que puedes preguntar, simular y entender activamente. Manuales, fichas de especificación y el export del bot dejan de ser archivos sueltos que hay que releer cada vez. Se vuelven notas conectadas en un vault de Obsidian, y un puñado de subagentes especializados hacen la primera lectura, el control de calidad y las preguntas por ti.

Claude Code OpenCode gratis · open source sin MCP · sin vectorización — v0
01el problema

Heredar un bot es releer
todo desde cero, otra vez.

Un proyecto RPA con años de antigüedad no vive en un solo lugar: vive repartido en manuales que ya nadie actualiza, fichas de Excel con reglas que cambiaron a mano, notas de correo, y el propio bot — que casi siempre sabe cosas que ningún documento dice.

Entender las reglas de negocio y las decisiones técnicas antes de poder tocar algo con confianza es, hoy, el costo más alto de dar soporte a RPA legado.

manuales
pdf / docx dispersos, versiones sin fecha clara
fichas xlsx
reglas de negocio en celdas, sin trazabilidad
notas sueltas
correos, chats, decisiones que nunca llegaron al manual
el bot mismo
la única fuente que dice qué pasa en realidad
02la idea

Un vault de Obsidian
haciendo de grafo de conocimiento.

Cada nota es un nodo del proceso. Cada relación está escrita, no implícita. El mismo archivo que usa un subagente para responder es el que tú puedes abrir y explorar visualmente.

documentos crudos → skills de lectura → vault (grafo en .md) → subagentes de consulta → tú, entendiendo el proceso
03cómo está armado

Skills + subagentes,
sin servidor ni infraestructura.

Principios de diseño

El vault es la fuente de verdad, no el chat — toda respuesta debe poder trazarse a una nota concreta.

Si el dato no está en el vault, el agente lo dice explícitamente — nunca completa el vacío con una suposición.

Todo corre desde la CLI: sin MCP, sin base de grafo formal, sin índice vectorial en esta primera versión. git clone y a trabajar.

rpa-cerebro/ ├── AGENTS.md # orquesta la sesión ├── CLAUDE.md # @AGENTS.md ├── vault/ # el grafo (notas .md) │ ├── _templates/ │ ├── _inbox/ # documentos sin procesar │ └── _staging/ # propuestas sin revisar ├── .claude/ │ ├── skills/ # método + lectura │ └── agents/ # 5 subagentes └── .opencode/agent/ # mismos 5, otro formato
04el archivo que orquesta todo

La sesión principal también
necesita instrucciones.

Los subagentes tienen su propio archivo. Pero nadie le decía a la sesión principal —quien decide a cuál delegar— cómo funciona el proyecto en conjunto. Ese es el trabajo de AGENTS.md.

# AGENTS.md (raíz, formato abierto) ## Cuándo delegar a cada subagente | dice... | delega a | |-------------------|--------------------| | "procesa este doc" | ingestion-agent | | pregunta directa | qa-agent | | "quiero entender" | tutor-agent | | "qué pasa si..." | simulation-agent | ## Regla de oro Si no está en el vault, decirlo — nunca completar con una suposición.
AGENTS.md
canónico. OpenCode lo lee de forma nativa al abrir el proyecto.
CLAUDE.md
un import: @AGENTS.md. Claude Code lo carga solo, sin duplicar contenido.

Es el primer archivo a leer o editar si algo del comportamiento general no te convence — antes de tocar un subagente individual.

07los subagentes

Cinco roles. Cada uno con
permisos de escritura acotados.

ingestion-agent
Lee vault/_inbox/ y propone notas.
escribe solo en vault/_staging/
graph-writer-agent
Toma el staging aprobado y lo escribe al vault final.
único que escribe en vault/ completo
qa-agent
Preguntas directas, respuesta concisa con cita.
solo lectura
tutor-agent
Modo socrático — preguntas guía, evalúa tu respuesta contra el vault.
solo lectura
simulation-agent
"Qué pasa si..." — recorre el grafo y muestra el camino.
solo lectura
08fuente especial

El export del bot manda
sobre "qué hace", no el manual.

El bot es la fuente más confiable de qué pasa en realidad. Cuando contradice al manual de negocio, el sistema no elige en silencio.

.atmx / .mbot
Enterprise 10/11 — exportar antes como XML/TXT
AAWorkbench.exe /export /sf: /df:
.aapkg
Automation 360 — se pone tal cual en _inbox/
se descomprime e inspecciona, sin asumir esquema fijo
manual dice
aprobación > $5.000.000
bot hace
aprobación > $4.500.000
→ discrepancia marcada, no resuelta en silencio
las dos notas se proponen; la revisión humana decide cuál es la vigente
09empezar

instalarlo. No hay paso extra.

git clone https://github.com/AND3SIL4/boots-understanding.git
cd repo

Nada que descargar aparte, nada que registrar en un marketplace. Los subagentes y skills se cargan solos al abrir la carpeta.

Antes de tu primera ingestión, revisa

nombre del proyecto
en README.md y AGENTS.md — sigue con el nombre temporal
vault/_templates/
solo si tu proceso necesita un tipo de nodo adicional
rpa-best-practices
amplíala si tu equipo tiene convenciones propias

No hace falta borrar ni tocar nada más — _templates/, _inbox/ y _staging/ ya están listos y vacíos.

10el flujo de uso

De un pdf en la carpeta
a una respuesta citada.

Clonar el repo

git clone y abrir la carpeta en Claude Code u OpenCode. Sin paso de instalación — AGENTS.md/CLAUDE.md dan contexto a la sesión principal desde el primer momento.

Revisar antes de arrancar

Nombre del proyecto en README/AGENTS.md, y si hace falta, ampliar vault/_templates/ o rpa-best-practices. El resto ya está listo.

Cargar los documentos crudos

Manuales, fichas xlsx, notas — y si lo tienes, el export del bot (.aapkg, o .atmx/.mbot convertidos) — todo a vault/_inbox/.

Ingerir

ingestion-agent lee cada archivo con la skill adecuada y propone notas en vault/_staging/<lote>/, sin tocar el vault final.

Revisar el staging

Corriges lo que haga falta. Presta atención a discrepancias marcadas entre el bot y los manuales — es la señal más valiosa.

Confirmar al vault final

graph-writer-agent mueve las notas aprobadas, marca estado: verificado y actualiza el overview del proyecto.

Consultar el conocimiento

Pregunta directa → qa-agent. Entender a fondo → tutor-agent. "Qué pasa si..." → simulation-agent.

11la regla que no se negocia

Un "no lo sé" trazable es más seguro
que una respuesta inventada.

Estos procesos suelen tocar pagos, RRHH o cumplimiento. El sistema está diseñado para preferir el silencio sobre la invención en cualquier punto donde el vault no tenga la respuesta.

nunca

Completar un vacío del documento fuente con una suposición presentada como hecho.

siempre

Citar la nota exacta que respalda cada afirmación, con su nivel de confianza.

ante la duda

Marcar la discrepancia y dejar que la revisión humana decida, nunca resolverla en silencio.
